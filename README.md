# 아웃리치 콘솔

공구 인플루언서 **발굴 → 제안 발송 → 회신 관리**를 한 화면에서 도는 내부 웹 콘솔.
[아웃리치 콘솔 프로토타입](https://claude.ai/code/artifact/cbfb67c0-fd05-442b-bb23-95c556300f86)의 12개 화면과
그 안에 적힌 설계를 실제로 동작하는 애플리케이션으로 구현한 것이다.

정적 목업이 아니다. 화면에 보이는 모든 수치는 요청 시점에 로컬 SQLite 를 훑어 계산하고,
버튼은 실제로 DB 를 바꾼다.

## 실행

```bash
npm install
npm run dev          # http://localhost:3000 — 첫 실행 시 DB 를 만들고 시드한다
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버. `data/app.db` 가 없으면 자동 생성·시드 |
| `npm run build` / `npm start` | 프로덕션 빌드·실행 |
| `npm run db:reset` | DB 를 지우고 다시 시드 |
| `npm test` | 로직·파이프라인 테스트 (30건) |
| `npm run test:e2e` | 브라우저 E2E (11건, Playwright) |
| `npm run typecheck` | `tsc --noEmit` |

환경 변수 `GONG_DB` 로 DB 경로를, `GONG_TODAY=YYYY-MM-DD` 로 기준일을 고정할 수 있다
(시드 데이터는 `2026-09-01` 기준으로 만들어져 있다).

    handle.ts     인스타 핸들 정규화 · 유사도
    clock.ts      날짜 헬퍼 · 기준일
    deals.ts      딜 상태 / D-DAY / 슬롯 점유 판정
    metrics.ts    케이던스 · 30일 딜 · 슬롯
    scoring.ts    적합도 산정 (배점 정의)
    scoring-context.ts  전 모집단 벌크 로더
    fit-cache.ts  캠페인별 적합도 물질화
    policy.ts     세그먼트 산출 · 정책 게이트
    importer.ts   소스 프로필 · 컬럼 매핑 추론 · 중복 검사 · 병합
    csv.ts        CSV 파서 · "10.8만" / "약 1시간 전" 파싱
    actions.ts    서버 액션 (발송, 분류, 큐 처리, 임포트 반영)

tests/

  pipeline.test.ts 시드 DB 위에서 점수·세그먼트·게이트·임포트

화면에는 클라이언트 자바스크립트가 거의 없다. 필터·정렬·페이지·드로어는 전부 URL 상태이고,
변경 동작은 폼 + 서버 액션이다. 새로고침해도 상태가 유지되고, 링크로 공유된다.

## 설계에서 지킨 것

**1) 메일링 — 주소는 하나, 스레드는 자동 매핑**

발송·수신 모두 `partner@dinostudio.kr` 한 개다. 담당자별 주소를 만들지 않는다.
Reply-To 의 `partner+cm_{token}.{handle}@` 플러스 주소가 회신을 캠페인·크리에이터에 연결하고,
Gmail `threadId` 가 `thread.thread_key` 가 된다. 회신이 들어오면 시퀀스는 `stopped_by_reply` 로 멈춘다.

**2) 데이터 유입 — 원문은 저장하지 않는다**

세 소스(맘캘린더 · 공구팡팡 · 인공) 모두 약관에서 자동 수집을 금지한다. 그래서 크롤러가 없고
CSV 업로드 경로만 있다. 저장하는 것은 파생 지표와 링크백뿐이고, 공구 항목은 셀러 인스타그램 원문으로 링크만 건다.

- 공통 자연키는 인스타 핸들 하나뿐 → `handle_norm`(소문자 + 구두점 제거)으로 매칭
- 맘캘 슬러그(`de-elisa-shop`)는 `.` 과 `_` 를 모두 `-` 로 치환한 결과라 역변환이 불가능하다.
  임포터가 슬러그를 **매칭 키 후보에서 아예 제외**한다
- 소스별 원 PK 는 `source_ref` 에 보존한다. 매칭에는 쓰지 않고 역추적과 핸들 변경 감지에만 쓴다
- 팔로워는 덮어쓰지 않고 `account_snapshot` 으로 쌓는다. `"10.8만"` 은 108,000 + 정밀도 ±500 으로 저장한다

중복 검사 임계: **≥0.95 자동 병합 / 0.80~0.95 사람 검토 / <0.80 신규**.
같은 소스 PK 인데 핸들이 다르면 유사도와 무관하게 **핸들 변경**으로 보고 검토 큐에 올린다.

**3) 매칭 — "누구에게" 가 아니라 "언제 누구에게"**

적합도는 합이 정확히 100 이 되도록 배점을 나눴다. 가산식에 상한을 씌우면 상위권이 전부
100 으로 뭉쳐 순위가 사라지기 때문이다.

| 축 | 배점 | 규칙 |
| --- | --- | --- |
| 카테고리 적합 | 0 ~ 55 | 카테고리 점유율 × 인접 카테고리 가중치 |
| 케이던스 타이밍 | 0 ~ 20 | 경과일 ÷ 평균 간격이 **1.0 일 때 만점**, 양쪽으로 감소 |
| 슬롯 여유 | −12 ~ +8 | 진행중·예정 공구가 많을수록 후순위 |
| 연락 경로 | −4 ~ +8 | 이메일 보유면 자동 시퀀스 가능 |
| 검증 큐레이션 | 0 ~ +5 | 맘캘린더 사람 검증 플래그 |
| 소스 신뢰도 | 0 ~ +4 | 몇 개 소스에서 확인된 레코드인가 |
| 브랜드 충돌 | −15 ~ 0 | 30일 이내면 점수와 무관하게 **제외**, 60일 −15, 90일 −5 |

연락 금지는 점수 이전의 문제라 산정 자체를 하지 않고 즉시 제외한다.
드로어를 열면 이 표가 그 크리에이터에 대해 실제로 어떻게 적용됐는지 항목별로 보인다.

**4) 컴플라이언스는 코드가 아니라 표가 통제한다**

`channel_policy` 테이블이 채널별 콜드 허용 · 실행 방식 · 야간 차단 · (광고) 표기 · 수신거부 ·
일 상한 · 쿨다운을 정의하고, 발송 게이트가 그 표를 읽는다. 인스타 DM 은 콜드 발송이 불가로
설정돼 있어 게이트를 통과할 수 없고, 항상 사람이 처리하는 작업 큐로만 나간다.

수신거부는 영구다. 스키마에 만료일 컬럼이 없어 설정할 수 없다.
인박스에서 회신을 `-4 연락 금지` 로 분류하면 핸들과 이메일이 즉시 `suppression` 에 등록되고,
그 크리에이터는 이후 모든 세그먼트에서 첫 단계에 걸러진다.

세그먼트 산출 순서도 그래서 중요하다 — **수신거부를 가장 먼저** 걷어낸다:

```
후보 (카테고리·팔로워) → − 수신거부 → − 쿨다운 → − 브랜드 충돌 → − 적합도·타이밍 → − 연락처 없음 → 최종 대상
```

연락처 없음으로 빠진 대상은 버리지 않고 인포크 제안 큐로 분기한다.

## 성능

적합도 정렬은 모집단 전체(1,742명)를 훑어야 한다. 크리에이터마다 개별 쿼리를 돌리면 1만 쿼리가 되어
첫 렌더에 9초가 걸렸다. 두 단계로 고쳤다.

1. `scoring-context.ts` 가 필요한 테이블을 한 번씩만 읽어 Map 으로 올린다
2. `fit_cache` 가 캠페인별 점수를 물질화한다 (기준일이 바뀌거나 수신거부·분류가 바뀌면 무효화)

첫 요청 183ms, 이후 47ms.

## 데이터에 대한 참고

시드는 프로토타입의 상세 샘플 12명을 그대로 넣고, 그 위에 세 소스 합집합 추정치 규모
(크리에이터 1,742명 · 딜 5,192건)를 결정론적으로 생성한다. 시드가 같으면 항상 같은 모집단이 나온다.

프로토타입에 적힌 "딜 34,650건 / 브랜드 8,150개" 는 insta-gong 웹에서 재현되지 않았다
(웹에는 인플루언서 510명만 노출되고 `/brands` 는 404). 앱 화면이나 로그인 뷰의 수치인지 확인이 필요하다.

## 알려진 제약

- 실제 Gmail API · 인스타그램 연동은 붙어 있지 않다. 발송은 `outreach_log` 와 `send_run` 에 기록되고
  작업 큐가 생성되는 데까지 동작한다. 외부 전송 어댑터를 끼울 지점은 `src/lib/actions.ts` 의 `startSend` 다
- 지속 모니터링이 필요하면 ① 각 사이트와 제휴 협의, 또는 ② 원천인 인스타그램 공개 게시물 직접 수집으로
  전환하는 두 경로를 권한다. 현재 구조는 "업로드된 스냅샷 사이의 차이 감지" 다
- `npm audit` 이 보고하는 postcss 취약점은 Next 빌드 툴체인의 전이 의존성이며 런타임 코드가 아니다
